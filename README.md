# HOI4 空戦シミュレーター

Hearts of Iron IV（HOI4）の空対空戦闘を、機体設計から比較できる非公式シミュレーターです。戦闘機・重戦闘機をモジュール式に設計し、連続戦闘の損失、複数試行による結果のばらつき、生産コストをブラウザだけで確認できます。

HTML・CSS・JavaScriptを `hoi4-air-combat-simulator.html` の1ファイルに収めています。インストール、サーバー、外部APIは不要です。

計算式、収録データ、資料との対応、推定部分は [SPECIFICATION.md](./SPECIFICATION.md) にまとめています。

## 主な機能

- 戦闘機／重戦闘機のモジュール式設計
- 制空任務／迎撃任務の切り替えと補正の自動反映
- 「空中戦重視の設計社」の機種別補正
- 1機の生産コストと、生産力300,000で生産できる機数の計算
- 陣営A・Bそれぞれの航空隊数、探知率、作戦効率の設定
- 1航空隊100機固定の航空隊単位計算
- 戦闘回数と試行回数の個別設定
- 損失を次戦へ持ち越す／毎戦リセットする方式の選択
- 通常空戦／空母戦の切り替え
- 手動探知率／Definesによる探知率推定の切り替え
- 航空隊ごとの確率的丸め
- 総撃墜、1戦平均、残存機、撃墜比、優勢率の表示
- 中央値、10%点、90%点、最小・最大、撃墜数分布の表示
- 代表試行の戦闘別ログ
- 機体設計の変更前後と、前回シミュレーションとの比較表示
- 15種類の空戦Definesの編集と初期値への復元

## すぐに使う

1. `hoi4-air-combat-simulator.html` をChromeやEdgeなどで開きます。
2. 陣営A・Bの「機体を設計」を押します。
3. 各兵装枠で許可された主兵装を選び、必要なら特殊装備を追加します。
4. 「この設計を反映」を押します。
5. 航空隊数、探知率、作戦効率、戦闘回数、試行回数を設定します。
6. 「シミュレーション開始」を押します。

初期設計では、機体・エンジン・設計社だけが選択されています。兵装と特殊装備はすべて空なので、初期状態の航空攻撃は0です。空戦を比較する前に主兵装を搭載してください。

## 飛行機設計

設計画面では次の要素を選択できます。

- 機体種別：戦闘機／重戦闘機
- 任務：制空任務／迎撃任務
- 設計社：設計社なし／空中戦重視の設計社
- 機体：各機種4世代
- 特殊装備：上段4枠
- エンジン・主兵装：普通戦闘機は下段に「エンジン、兵装1、兵装2、兵装3、兵装4、兵装5、兵装6」の順で配置。重戦闘機は「兵装1、兵装2、エンジン、兵装3、兵装4、兵装5、兵装6」の順で配置
- エンジン：1枠、必須
- 兵装：6枠、すべて任意。ただし機体と設計思想の搭載条件に従って選択肢を制限

兵装欄を押すと候補一覧が開きます。候補へカーソルを合わせるかキーボードでフォーカスすると、右側が「設計性能（仮選択）」へ切り替わり、航空攻撃・防御・速度・機動性・重量・コスト・生産可能数などを選択前に比較できます。候補をクリックした場合だけ設計へ確定し、一覧からカーソルを外すか閉じると確定済み設計の性能へ戻ります。

普通戦闘機では、兵装1が機首用の軽機関銃・重機関銃・単装機関砲、兵装2が機関銃・連装機関砲・対戦車砲、兵装3が戦闘機設計思想で追加される機関銃・連装機関砲です。兵装4は落下増槽・吊り爆弾・雷装、兵装5はフロート・吊り爆弾・ロケットレール、兵装6は吊り爆弾・ロケットレールを選択できます。

重戦闘機では兵装1と兵装2に中型機体の許可カテゴリを適用し、兵装3では前方兵装に加えて軽機関銃・重機関銃・機関砲の単装／連装防御砲塔を選択できます。防御砲塔は航空攻撃ではなく航空防御を増加させ、重量・速度・機動性・コストにもMOD値どおり影響します。兵装4では爆弾槽・航空魚雷・対艦ミサイル、兵装5では飛行艇・吊り爆弾・ロケットレール、兵装6では吊り爆弾・ロケットレールを選択できます。これらを搭載しても重戦闘機として空戦比較できます。

兵装5へ飛行艇を搭載すると、MODの `allowed_module_categories` に従って三発エンジン、三発ジェットエンジン、三発軸流式ジェットエンジンが追加されます。飛行艇を外すと三発系は選択できなくなり、双発エンジンへ戻ります。戦闘機側も、兵装4～6で機体定義が許可する増槽・爆装・雷装・フロートを選択できます。

同じ特殊装備を複数枠へ搭載することはできません。空対空レーダーI・IIや無線航法I・IIのような同一系列の新旧装備も併載できません。また、普通戦闘機の兵装3へ胴体用20mm機関砲×2を搭載すると、兵装1の単装20mm／30mm機関砲とは競合します。重量が推力を超える設計も反映できません。機種を切り替えると、その機種の初期状態へ切り替わり、兵装と特殊装備は空になります。

### 設計社補正

| 機体種別 | 最高速度 | 機動性 |
|---|---:|---:|
| 戦闘機 | +5% | +5% |
| 重戦闘機 | +5% | +10% |

### 任務補正

- 戦闘機は迎撃任務で航空攻撃+5%。
- 重戦闘機には機種固有の迎撃補正はありません。
- 空対空レーダーのように迎撃専用補正を持つ装備は、機種固有補正とは別に加算されます。

設計画面には、現在反映中の設計から変化する数値が色付きで表示されます。設計を確定するまで陣営の実データは変更されません。

## 戦闘回数、試行回数、損失持ち越し

- **戦闘回数**：1試行の中で連続して実施する空戦の数です。
- **試行回数**：同じ条件を初期状態から何セット再実行するかです。

例として「戦闘回数30、試行回数1,000」なら、30戦を1セットとして1,000セット計算します。

「損失を次戦へ持ち越す」が有効な場合、撃墜された機体は次の戦闘に参加できません。一方が全滅すると、その試行は予定戦闘数より早く終了します。

無効な場合は、各戦闘を毎回同じ初期機数から開始します。総撃墜は全戦闘分を合計し、残存機は最後の1戦の結果を示します。この場合の優勢率は残存機ではなく総撃墜で判定します。

## 探知率

通常は「手動入力」を推奨します。陣営Aの探知率はAがBを、陣営Bの探知率はBがAを発見できる割合です。

「Definesから推定計算」を選ぶと、支配地域割合、レーダー寄与、自軍残存機数、夜間補正から探知率を算出します。これはDefinesの影響を比較するための簡略モデルであり、ゲーム内部の探知処理を完全再現するものではありません。

## 結果の見方

### 代表試行

複数試行のうち最初の1セットです。総撃墜、1戦平均、残存機、撃墜比を表示し、戦闘ログと対応します。

### 複数試行の統計

全試行について、平均、中央値、10%点、90%点、最小・最大、撃墜数分布を集計します。2回目以降は、前回実行時からの平均撃墜、平均残存、優勢率の変化も表示します。

### 戦闘ログ

代表試行の各戦闘について、開始機数、攻撃参加機数、期待撃墜、実撃墜、終了時残存を表示します。

## 詳細設定

空戦ダメージ、機動性、速度、参加機数、探知に関係する15種類のDefinesを変更できます。初期値は提供された `00_defines.lua` から抽出した値です。「00_defines.lua の値に戻す」で一括復元できます。

Defines名の `MULTILPIER` と `AIRCRAFTS` は、ゲーム側ファイルの綴りをそのまま使用しています。

## GitHub Pagesで公開する

1. `hoi4-air-combat-simulator.html` を `index.html` という名前でリポジトリ直下へ置きます。
2. GitHubのリポジトリで `Settings` → `Pages` を開きます。
3. Sourceを `Deploy from a branch` にします。
4. Branchを `main`、フォルダを `/(root)` にして保存します。
5. GitHub ActionsまたはPages画面で公開完了を確認します。

公開URLは通常 `https://ユーザー名.github.io/リポジトリ名/` です。GitHub PagesはURLを知っている人だけに限定する仕組みではなく、基本的には一般公開です。

更新するときは、リポジトリの `index.html` を新しい内容へ置き換えてコミットします。毎回リポジトリを作り直す必要はありません。

## 動作環境とデータの扱い

JavaScriptが有効な現在のChrome、Edge、Firefox、Safariを想定しています。入力と計算はすべてブラウザ内で行われ、外部API、Cookie、データベースは使用しません。ページを再読み込みすると、未保存の入力や実行結果は初期状態へ戻ります。

## 既知の制限

- HOI4のゲームコードそのものを実行しているわけではありません。
- 航空隊は100機固定で、陣営内に異なる性能の機体を混在できません。
- 経験値、エース、天候、事故、補充、燃料、航続距離不足、情報値などは扱いません。
- 夜間ペナルティ補正と航続距離は設計値として表示しますが、空戦ダメージには使用しません。
- 技術研究や年代による装備ロックは再現していません。
- 空対空戦闘向けの機体・モジュールだけを収録し、爆撃・対艦装備は省略しています。
- 探知Definesからの探知率計算や航空隊への攻撃配分には推定が含まれます。
- ゲーム本体やMODの更新で数値・処理が変わる可能性があります。
- 条件によっては試行ごとの乱数差が大きいため、設計比較には十分な試行回数が必要です。
